# African location fields

Country, province/region and city/town are independent required controls on student registration, tutor registration, tutor application and contact. Country is an ISO alpha-2 code; province and city are names. Changing a parent clears incompatible descendants. Explicit Other selections reveal required name inputs, capped at 160 characters. Location metadata grants no roles or permissions.

The offline GeoNames snapshot was retrieved on 22 October 2026. It contains 58 African countries and territories, 833 first-level administrative divisions and 13,594 deduplicated populated-place names. These are not 58 sovereign countries or an exhaustive list of every settlement. Country classification follows GeoNames continent AF. The cities500 source includes places with population over 500 and administrative seats. Eighty-one places without a matching administrative division were omitted; Other supports these and smaller/unlisted places.

Sources: https://download.geonames.org/export/dump/countryInfo.txt, admin1CodesASCII.txt, cities500.zip and readme.txt. Dataset license: [GeoNames CC BY 4.0](https://www.geonames.org/export/), https://creativecommons.org/licenses/by/4.0/. Source checksums and extraction criteria are in frontend/public/data/locations/source.json. Place names were normalized to Unicode NFC, deduplicated and sorted. This adaptation groups cities by the first-level division. Source data is provided without accuracy or completeness guarantees. No paid lookup provider or runtime third-party request is used.

The country index is bundled with the control; each country's places load on demand from same-origin static JSON. Server validation uses matching lazy data. Django holds the same snapshot and independently validates selections. Keep all three copies and both indexes synchronized when refreshing the snapshot. The location unit tests verify every country, both frontend copies and the index.

Signup stores separate values in existing Supabase account profile metadata. Contact and tutor application add distinct Django fields via additive migration 0016; old rows and old clients remain compatible. Historical free-text locations are retained without unreliable backfills. The tutor application's human-readable location summary remains for compatibility. On the legacy Cloudflare D1 contact fallback, location labels are appended to the saved message because that historical table has no location columns; Django is the structured primary storage on Render.

Deploy the compatible backend/migration before the frontend. Test all four forms against the target environment before promotion. Rollback application code while retaining the added columns; do not reverse the migration on a live database. No deployment is performed by the location test workflow.

The JavaScript-disabled location picker at /locations uses GET to update dependent choices before returning to an allowlisted form. It does not accept passwords, tokens or files. Browser CI copies the real tutor ApplicationForm into an isolated test page only during the test build; no auth bypass is added to release code, and no application build is uploaded or deployed. All browser tests intercept POST requests and use synthetic values.
