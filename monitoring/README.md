# Amaris production monitoring — isolated Render Blueprint

This monitoring branch does not alter or redeploy Amaris's live Django and Next.js services.

## Components

- **Prometheus:** Render **private service**, Frankfurt, Standard 1 CPU/2 GB, 1 GB persistent disk at `/prometheus-data`, 7-day retention, scrapes its own process, Django's existing `/metrics`, and Flower's `/metrics`.
- **Flower:** Render **private service**, Frankfurt, Starter 512 MB; observes existing `amaris-production-broker` via a Render `fromService` secret reference. It DOES NOT run a new Celery worker or queue consumer.
- **Grafana:** Render **web service**, Frankfurt, Starter 512 MB with persistent 1 GB disk at `/var/lib/grafana`. Has autogenerated admin password, no anonymous access, HTTPS cookies, provisioned read-only Prometheus data source and an observation-only dashboard. The user should rotate the generated admin password after initial sign-in.
- **cAdvisor:** Not deployable for true Render-host metrics; official cAdvisor needs host Docker/socket/cgroup mounts and in some setups privileged access. The optional `cadvisor/docker-compose.yml` is **only** for an independently controlled Docker host, not Render. No cAdvisor data is asserted before verified collection.

## Security and caveats

- Grafana is the only publicly accessible monitoring UI; its login is required. No public Prometheus or Flower endpoints.
- A Prometheus job scraping an existing Django URL only establishes health *after* an actual successful scrape. A metrics series name can change as django-prometheus is upgraded.
- Render's service metrics and logs are distinct from Prometheus instrumentation. This Blueprint does not ingest Render's proprietary CPU/HTTP metrics automatically. If data is not scraped, the panel must show N/A, not guesses.
- Existing Django `/metrics` may be publicly reachable; perform a sensitive-label review and add authentication before expanding exposure to sensitive metrics.
- **Celery worker availability is not proven by Flower's own up=1.** Inspect Flower's worker/task panels separately; queue broker and workers may be absent.
- cAdvisor on a different Docker host only measures that host, **not** managed Render containers. Never label it as Render host metrics.
- No production secrets, database credentials, broker URLs, or admin passwords belong in GitHub files.
- A durable TSDB needs a disk. If its 1 GB disk fills, increase size after reviewing actual retention/ingestion; never show extrapolated storage measurements as facts.
