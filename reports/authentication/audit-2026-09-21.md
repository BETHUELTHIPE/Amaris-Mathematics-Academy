# Authentication audit — 21 September 2026

Scope: registration, verification codes/links, login, recovery, logout, session renewal, student API authentication and profile isolation.

Source base: `4624cdf516e5908eb46a16e84f9ed7f758c080fa` (`main`). Local implementation commit: `3c586e0`. Changes are proposed on `fix/authentication-flow-audit`; they have not been deployed by this audit.

## Fixed

- Read confirmation status from the validated Supabase Auth user (`email_confirmed_at`), rather than a missing top-level JWT claim. User-editable metadata cannot grant verified access; anonymous users are excluded.
- Send successful password-recovery callbacks to `/reset-password`, retaining safe internal destinations for other callbacks. Invalid recovery links offer another reset request.
- Permit login forms without the optional `next` field.
- Report failed verification/reset email requests and failed signout honestly.
- Forward rotated cookies to both the downstream server request and browser; preserve cleanup cookies on expired-session redirects.
- Include lessons in session refresh and private caching rules. Auth pages, callbacks, responses setting cookies and personalized public responses are not publicly cacheable. Verification-code submissions use the auth rate limiter.
- Use a native six-digit verification input with one-time-code autofill; allow an email to be entered when the verification page is opened directly.
- Reject expired/malformed backend tokens before cache lookup and cap cached validation at token expiry. The unverified expiry decode grants no identity; the Supabase Auth endpoint still validates credentials.
